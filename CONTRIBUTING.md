# Contributing Guide

Thank you for contributing to this Bugle Technologies project.

This repository is used for website design, page development, static previews, and related project work. Please follow this guide to keep the project organized, professional, and easy to review.

## Project Purpose

This repository may include:

- HTML page designs
- CSS styling
- JavaScript interactions
- Website redesign work
- Multiple page versions
- GitHub Pages previews
- Client or internal review versions
- Project documentation and assets

## Repository Ownership

This repository is maintained for [BugleTech](https://github.com/bugletech) project work.

Contributors may use authorized GitHub accounts to contribute, but all project work should follow Bugle Technologies project standards, repository guidelines, and review processes.

## How to Contribute

You can contribute by:

- Creating or improving page designs
- Fixing layout or responsive issues
- Improving HTML, CSS, or JavaScript
- Updating content or assets
- Cleaning file structure
- Reporting bugs or design issues
- Suggesting improvements

## Branch Naming

Use clear and meaningful branch names.

Good examples:

```text
home-page-v1
landing-page-redesign
fix-navbar-responsive
update-client-preview
pricing-page-v2
```

Avoid unclear names:

```text
new
changes
final
final2
latest
```

## Commit Messages

Use clear and meaningful commit messages.

Good examples:

```text
Add homepage hero section
Fix mobile navbar layout
Update client preview content
Improve footer spacing
Add responsive pricing page
```

Avoid unclear commit messages:

```text
changes
update
final
new
fix
```

## Pull Request Guidelines

Before opening a pull request:

- Make sure the page opens correctly
- Check the design on desktop and mobile
- Remove unused files where possible
- Use meaningful commit messages
- Explain what changed in the pull request description
- Include a GitHub Pages preview link if available

Recommended pull request format:

```md
## What changed

- Added new homepage layout
- Updated navbar design
- Improved mobile spacing

## Preview

https://bugletech.github.io/Taigus_IML-Solutions/

## Notes

Add any review notes, known issues, or pending changes here.
```

## GitHub Pages Preview

If this project uses GitHub Pages, include the preview link in the README or pull request.

Example:

```text
https://bugletech.github.io/Taigus_IML-Solutions/
```

For client-facing previews, use only the approved preview link shared by the maintainer or Bugle Technologies project owner.

## Design Versions

If you create multiple versions of a page, name them clearly.

Good examples:

```text
home-v1
home-v2
home-dark-version
landing-client-version
pricing-clean-layout
```

Avoid confusing names:

```text
final
final2
new-final
latest-final-real
```

## File and Folder Structure

Keep files organized and easy to understand.

Recommended structure:

```text
project-root/
├── designs/
├── assets/
│   ├── images/
│   ├── icons/
│   └── fonts/
├── css/
├── js/
├── CODE_OF_CONDUCT.md
├── CONTRIBUTING.md
├── NOTICE.md
└── README.md
```

## Code Style

Please follow these basic rules:

- Keep HTML readable and properly indented
- Use meaningful class names
- Keep CSS organized
- Avoid unnecessary duplicate code
- Use responsive design where needed
- Keep image file names clear and lowercase
- Remove unused files before final review

Good file names:

```text
hero-background.jpg
logo-primary.svg
home-page-preview.png
```

Avoid file names like:

```text
IMG_1234-final-new-copy.png
newww.png
final-final.png
```

## Reporting Issues

When reporting an issue, include:

- Page or file name
- Device or screen size
- Browser name
- Expected result
- Actual result
- Screenshot if helpful

Example:

```text
Page: index.html
Device: Mobile
Browser: Chrome
Issue: Navbar overlaps the hero title
Expected: Navbar should stay above the hero section
```

## Confidentiality

Some repositories may contain client-related project work, preview designs, internal project material, or assets.

Do not share project files, preview links, screenshots, or client-related content outside the approved project context without permission from Bugle Technologies or the authorized project owner.

## Code of Conduct

By participating in this project, you agree to follow the [Code of Conduct](./CODE_OF_CONDUCT.md).

## Questions

For project-specific questions, contact the maintainer or the relevant Bugle Technologies project owner.
